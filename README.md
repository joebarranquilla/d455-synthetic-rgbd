# d455-synthetic-rgbd

Generates fake (synthetic) RGB-D images that look like they came from an Intel RealSense D455
camera held by a robot arm ("eye-in-hand"). The scene is a bin full of aluminium T-slot profiles and
L-brackets. Every image comes with perfect ground truth (depth, normals, object masks, object poses),
so it can be used to train and test pose-estimation / localization methods.

This is phase 1: clean ground-truth rendering only. Sensor noise levels and IR images come later.

## Quick start

```
python3 -m venv .venv && make deps    # install Python packages + BlenderProc extras
make sample                           # render 5 dev samples + montage, prints seconds per sample
make test                             # unit tests (fast, no GPU or Blender needed)
```

Render your own data (needs a GPU; first run downloads Blender automatically):

```
.venv/bin/blenderproc run scripts/render_samples.py --split dev --n 100 --seed 0
```

- `--split dev` is for tuning and debugging. `--split test` is frozen and never used for tuning.
- `--seed` makes everything reproducible: same seed and config give the same scenes.
- Output goes to `data/<split>/<id>/` (or `--out DIR`). `data/` and `outputs/` are never committed.

## What the pipeline does, step by step

For every sample, `scripts/render_samples.py` runs these steps:

1. **Load configs** from `configs/`. All numbers live there, none are hard-coded.
2. **Camera model** (`configs/d455.yaml`): 848x480 pixels, 87 deg horizontal field of view, 95 mm stereo
   baseline. The intrinsics `fx, fy, cx, cy` are derived from these.
3. **Build the parts** (`geometry.py`, `parts.py`): exact meshes are generated by plain maths, with no Blender.
   - T-slot profiles in 20, 30 and 40 mm sizes (4 slots, centre bore), 0.10-0.40 m long.
   - L-brackets with 30 mm legs, 3 mm thick, 2 holes per leg.
   - Each part gets a random metal material (silver or black anodised, brushed aluminium, zinc).
     Roughness, metallic and anisotropy are drawn from the ranges in `scene.yaml` and saved in the metadata.
4. **Build the scene** (`scene.py`): a table with a 0.5 x 0.4 m bin. 4-12 parts are dropped in from a
   random height and settle with rigid-body physics, so the piles look natural. Parts that fall outside
   the bin are removed. 1-3 random area lights and a dim world colour light the scene.
5. **Place the camera** (`scene.py`): 0.45-0.9 m above the bin, tilted 0-45 deg from vertical, random
   rotation around the viewing axis, plus a small position jitter.
6. **Render** (`render.py`, Blender Cycles on GPU), in two passes:
   - *Geometry pass* (1 sample per pixel, **no anti-aliasing**): distance, normals and object-id masks.
     No anti-aliasing is important, otherwise edge pixels would blend two objects and give wrong depth.
   - *Colour pass* (32 samples per pixel, denoised): the RGB image.
7. **Convert and save**: distance along the viewing ray is converted to z-depth, pixels outside
   0.4-6.0 m are marked invalid, normals are rotated into the camera frame, and files are written.
8. **Print timing**: seconds per sample, and the mean at the end.

## What one sample contains

Folder `data/<split>/<id:05d>/`:

| File | Content |
|------|---------|
| `rgb.png` | 8-bit colour image. |
| `depth_gt.npy` | float32, metres. **Z-depth** (distance along the optical axis, not along the ray). `0` = invalid. |
| `normals.npy` | float16, HxWx3 unit surface normals in the camera frame. |
| `inst.png` | uint16 instance ids. `0` = background, `1..N` = one id per part. |
| `cls.png` | uint8 class ids. `0` background, `1` profile, `2` bracket, `3` other. |
| `meta.json` | Camera `K`, `T_world_cam`, `baseline_m`, `seed`, and a list of objects (see below). |

Each object in `meta.json` has: `id`, `class`, `dims_m`, `T_cam_obj` (its pose in the camera frame),
`material` (`roughness`, `metallic`, `anisotropy`, `type`) and `n_visible_px` (pixels visible in the image).

Notes:
- `inst.png` and `cls.png` look almost black in an image viewer because the values are tiny (0, 1, 2...).
  They are labels, not colours. `outputs/montage.png` shows them colourised.
- Conventions: SI units (metres). Camera frame is x right, y down, z forward.

## Repository layout

```
configs/    d455.yaml (camera), scene.yaml (parts, materials, lights, camera poses, render settings),
            ladder.yaml and loc.yaml (empty, reserved for later phases)
src/d455sim/
  geometry.py   profile/bracket maths, surface point sampling, symmetries, dist->z-depth. No Blender.
  parts.py      turns the geometry into Blender objects with materials.   (uses bpy)
  scene.py      table, bin, physics drop, lights, camera pose.            (uses bpy)
  render.py     Cycles rendering and the geometry/colour passes.          (uses bpy)
  config.py     loads YAML and derives the camera matrix K.
  meta.py       builds and validates meta.json.
scripts/    render_samples.py (main CLI), montage.py (rgb | depth | inst | normals picture)
tests/      pytest: cross-section areas, mesh volumes, dist->z-depth, meta schema
```

Only `parts.py`, `scene.py` and `render.py` import `bpy`, so everything else can be tested without Blender.

## Good to know

- Values in `d455.yaml` are marked `# VERIFY` and should be checked against the Intel datasheet.
- Symmetries (profile: 180 deg flip and 4-fold turn about its long axis; bracket: mirror, set in config)
  are provided by `geometry.symmetries()` for symmetry-aware pose evaluation later.
- After the `v1-freeze` git tag, parameters must not change, so the test split stays comparable.

## Phase 2: sensor degradation (`src/d455sim/sensor.py`, `configs/ladder.yaml`)

Ideal `depth_gt.npy` is turned into D455-like depth by pure functions (no Blender): noise (disparity domain),
quantisation, coherent dropout (grazing angle / shiny surfaces), edge effects (baseline shadow, flying pixels, fattening).
Levels are cumulative: L0 ideal, L1 +quant, L2 +noise, L3 +dropout, L4 +edges; `Lfull_minus_<effect>` leaves one out.
All coefficients are heuristics and need calibrating against a real D455.

```
.venv/bin/python scripts/make_depth.py --split dev --level L3      # writes depth_L3.npy per sample
.venv/bin/python scripts/make_depth.py --split dev --drop edges    # writes depth_Lfull_minus_edges.npy
.venv/bin/python scripts/validate_sensor.py --split dev            # outputs/validate/{metrics.json,*.png}
```
